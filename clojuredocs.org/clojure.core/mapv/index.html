    clojure.core/mapv¶

    View this page on ClojureDocs

    Type: function Added: Clojure 1.4 Examples: 3 Runnable: 3 
    ([f coll] [f c1 c2] [f c1 c2 c3] [f c1 c2 c3 & colls])

    Returns a vector consisting of the result of applying f to the set of first items of each coll, followed by applying f to the set of second items in each coll, until any one of the colls is exhausted. Any remaining items in other colls are ignored. Function f should accept number-of-colls arguments.

    Note by num1¶
    

    Like map but returns a vector. In most cases equivalent to calling (into [] (map f c1 c2 ...)). Is much faster than map (but is not lazy!) in the (mapv f coll) case.
    

    Note by KingMob¶
    

    It's not necessarily true at all that mapv will be faster than map. mapv (and related fns like filterv) have increased memory needs (creating unused values, realizing intermediate sequences, etc) that hurt it.
    

    Here's a simple example showing how mapv/filterv can be slower. (Benchmarked with criterium.)
    

    (let [nums (range 10000000)]
  (bench
    (reduce +' 0 (filter even? (map #(* % %) nums))))

  (bench
    (reduce +' 0 (filterv even? (mapv #(* % %) nums)))))

    
and the results, showing map is actually a little faster than mapv:
